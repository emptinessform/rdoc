## 폰트 캐시 (포크 rev 614a558)

가설 검증: `--no-default-features`(번들 폰트만) 빌드에서 키 입력당 재조판
1,144ms → 157ms ⇒ 지연의 85%가 폰트 처리임을 확인.

원인 2개, 패치 2개 (oxml-layout/src/font.rs):
1. `FontManager::new()`가 레이아웃 호출마다 `fontdb load_system_fonts()`로
   설치 폰트 전체를 재스캔·재파싱 → **번들+시스템 DB를 프로세스 전역 1회
   구축(OnceLock), 이후 clone** (face 테이블만 복제).
   → 1,144ms → 397ms.
2. `with_face_data`가 파일 기반 face(시스템 폰트)를 해석 때마다 디스크에서
   재독취+복사 (CJK 13~20MB) → **경로+인덱스 키 전역 바이트 캐시**.
   메모리 내 face(번들·사용자 주입)는 비캐시 유지.
   → 397ms → **169ms** (포크 rev 핀 재검증 211ms — 총 5.4~6.8배).

검증: 우리 단위 테스트 7/7, 코퍼스 14/14 (파일당 레이아웃 600~2300ms →
1ms대), 업스트림 oxml-layout 테스트 62+3 통과.

이 패치는 wasm(시스템 폰트 없음)에는 영향 없음 — wasm 63페이지 키 입력
~590ms의 병목은 셰이핑/페이지네이션 + 14MB SVG 재생성/DOM 교체.
