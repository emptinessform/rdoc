# 2026-08-23 — S47: 스크롤·썸네일 패널 레이아웃 개편 (사용자 피드백)

## 배경 (피드백 4건 중 1~3)

① 가로 스크롤 없음(확대 시 왼쪽 잘림), ② 썸네일이 확대/축소 시
편집영역을 가림, ③ 썸네일을 왼쪽 패널 형태로. (④ 표 삽입·d&d는
S48/S49로 분할.)

## 원인·설계

- ①은 flex 가운데 정렬의 고전 함정: 컨테이너보다 넓은 항목을
  center 정렬하면 왼쪽 오버플로가 도달 불가로 잘림.
- ②③은 썸네일이 position:fixed 오버레이라서 발생.
- 개편: body를 세로 flex(헤더 + #app), #app은 가로 flex —
  **#thumbs가 실제 컬럼 패널**(공간 차지, 겹침 불가) + **#main이
  스크롤 컨테이너**. #pages는 `width:max-content; min-width:100%`로
  좁으면 가운데, 넓으면 가로 스크롤.
- 스크롤 주체가 window→#main으로 바뀌어 4곳 이관: 지연 렌더 드레인
  리스너, 캐럿 추적(drawCaret), 드래그 자동 스크롤(스크롤러 상하단
  가장자리 기준), 찾기 매치 점프. 썸네일 클릭 scrollIntoView는
  컨테이너 내부에서 그대로 동작.

## 검증 (실측)

- 200% 확대: #main scrollWidth 1448 > clientWidth 1280, scrollLeft
  0에서 페이지 왼쪽 가장자리 24px 가시 — **왼쪽 잘림 해소**.
- 썸네일 열림: 패널 오른쪽 경계 ≤ 본문 왼쪽 경계 (겹침 0) —
  150% 확대+패널+가로 스크롤 공존 스크린샷
  docs/evidence/s47-panel-hscroll.png.
- 배터리: window.scrollY를 보던 스위트 2건(thumbs, ux4)을 #main
  기준으로 갱신(설계 변경의 정당한 여파) 후 **44/44 그린**.
- 모바일(390px): 패널은 토글 시 132px 컬럼(본문 241px) — 오버레이
  대신 패널 요구 반영.
