# 2026-08-21 (4) — S3 착수: 성능 기준선 + provenance 제안 초안

## 성능 기준선 (src/bin/bench.rs, 63페이지 문서: 문단 701 + 표 14)

| 측정 | 결과 | 게이트 대비 |
|---|---|---|
| 네이티브 cold 레이아웃 | 2,394ms | — |
| 네이티브 키 입력당 전체 재조판 (n=10) | **평균 1,144ms** (min 889) | 30ms의 38배 |
| 전체 페이지 SVG 재생성 | 178ms, 13.9MB | — |
| wasm 초기 로드+렌더 (63p) | 655ms | — |
| **wasm 키 입력당** (n=5, 렌더+DOM 교체 포함) | **510~752ms** | 30ms의 ~20배 |

결론: S3 게이트(<30ms/키) 달성에는 (a) **문단 단위 증분 레이아웃**(지배 비용),
(b) **변경 페이지만 SVG/DOM 갱신**(178ms + 13.9MB DOM 교체) 둘 다 필요.

단서: wasm(주입 폰트 1개+번들)이 네이티브(시스템 폰트 탐색)보다 빠름 —
레이아웃 호출마다 폰트 로딩이 반복되는 것으로 추정. 증분화 이전에 폰트
캐시만으로도 네이티브 상당 폭 개선 가능성. 프로파일링은 증분 작업에서.

## provenance 제안 초안

`upstream/provenance-proposal.md` 작성 (게시 전 사용자 확인 대기).
핵심: `TextSegment`/`GlyphRun`에 `source: Option<SourceSpan { node: u64,
char_start: u32 }>` — oxml-layout은 불투명 유지(복사 + 분할 시 char_start
가산만), 인코딩은 rdocx-layout 소관. 텍스트 매칭 한계 데이터(156/174, 표 셀
0%, CJK 음절 파편화, 반복 문구 모호성)로 동기 부여, PR 구현 제안 포함.
