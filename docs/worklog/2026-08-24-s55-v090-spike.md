# 2026-08-24 — S55: v0.9.0 이행 스파이크 (기능 OK, 성능 2~3× 회귀)

## 목표·범위

업스트림 v0.9.0 출시(#42/#43이 F-X048로 수용)에 따라 ① dense-form
포크 커밋을 폐기할 수 있는지, ② s52 시점 에디터 성능 회귀가 해소됐는지
판정한다. 프로덕션 핀은 건드리지 않는다(스파이크 후 원복).

## 한 일

- 포크 브랜치 **svg-poc-0.9**(= v0.9.0 + 우리 에디터 스택 30커밋,
  b3e0143) 조립. 체리픽에서 확인된 사실:
  - `add_run_inheriting_mark`는 v0.9.0에 **이미 수용됨** → 우리 커밋 폐기.
  - **dense-form 4커밋(074ee1f/f339511/3cd488b/bdfefa3)은 아예 제외**하고
    조립 — F-X048로 대체 가능한지 보기 위함.
  - 리베이스 낙진 정리 1커밋(word-wrap 헬퍼 재배치, 새 Figure 분기의
    tab-interval 인자, rpptx-render LineBreakParams 신규 필드).
- rdoc 측 적응 **3곳**(패치 보관: docs/upstream/2026-08-24-rdoc-v090-
  adaptation.diff):
  1. `PositionedElement::MarkedContent`(태그드 PDF 구조, v0.9.0 신규)를
     SVG 이미터에서 재귀 처리 — 없으면 **전 페이지가 빈 렌더**.
  2. 같은 처리를 `collect_hits`에도 (없으면 히트 0 → 편집 전면 불가).
  3. 페이지 해시에도 반영.
  4. 엔진 핸드오프 API 교체: `take/set_layout_engine` →
     `transfer_reusable_bundled_fallback_layout_from(source, fonts)`.

## 검증 (실측)

- **기능 등가**: 코퍼스 14종 페이지/런/매핑 수치 0.8과 **완전 일치**
  (dense-form 커밋 없이!), 브라우저 배터리 **50/50 그린**, 네이티브
  lib 9/9, poc SVG 167KB·히트 272. 포크 테스트 172 pass / 3 실패는
  환경 문제(`shasum` 미설치, v0.9.0 자체 결함 아님).
  → **dense-form 포크 4커밋 폐기 가능**(F-X048이 대체).
- **성능 회귀**(동일 세션 교차 측정, 63p 벤치 문서):

  | 지표 | 0.8 핀 | v0.9.0 | 배율 |
  |---|---|---|---|
  | 네이티브 키 입력 min | 36~40 ms | 71~88 ms | ~2.1× |
  | 브라우저 타이핑 mean | 96~113 ms | 317~336 ms | ~3.0× |
  | 브라우저 로드 | 4.6~5.7 s | 15.0~17.7 s | ~3.0× |
  | 브라우저 undo | 148~165 ms | 608~614 ms | ~4.0× |
  | 셀 병합 | 152 ms | 335~365 ms | ~2.3× |

  노트 연산은 s52 때의 ~10× 회귀가 **해소**(동등 수준).

## 함정 (기록)

- **`[patch."<git url>"]`는 rev 고정 의존성에 적용되지 않는다** —
  cargo가 `url?rev=X`를 별개 소스로 보기 때문. 처음 A/B는 양쪽 모두
  0.8로 빌드돼 무효였고, `cargo tree`의 "patch was not used" 경고로
  발견. 올바른 방법은 의존성을 path로 임시 교체하는 것.

## 결론·후속

- 이행은 **기술적으로 가능**하고 포크가 크게 슬림해지지만(에디터
  스택만 남음), 에디터 hot path가 2~3× 느려져 **지금 이행은 보류**.
- 프로덕션은 svg-poc-0.8(29a4a5c) 유지. 스파이크는 브랜치 svg-poc-0.9와
  위 패치로 보존 — 성능 개선 후 즉시 재개 가능.
- 이 수치는 업스트림 성능 피드백(#39 후속) 게시의 근거가 된다.
