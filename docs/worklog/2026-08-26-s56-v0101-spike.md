### 근본 원인 — 재시작 페이지네이션 적격 게이트

v0.10.1 `crates/rdocx-layout/src/engine.rs:1236`:

```rust
let restart_record_eligible = sections.len() == 1
    && input.document.background_xml.is_none()
    && input.footnotes.is_none() && input.endnotes.is_none()
    && !document_wraps
    && sections[0].header_footer.is_none()
    && ...all(|(content, block)| restart_record_block_is_safe(block));
// restart_record_block_is_safe: paragraph.lines.len() <= 2
//   && anchored.is_empty() && heading_level.is_none()
//   && !keep_next && !keep_lines && 노트/이미지/그룹 없음
```

**문서 전역 all-or-nothing**이다. 3줄 이상 문단이 **하나라도** 있거나,
각주·미주·머리글/꼬리글이 있으면 문서 전체가 증분 경로에서 빠져
키 입력마다 전체 페이지네이션을 돈다.

0.8(우리 포크 F-X040 후보) `paginator.rs`의 `cacheable`은 ① 단일 섹션
② 블록 지문 존재 ③ 부동 도형 없음 — 이 셋만 본다. 각주·머리글·문단
줄 수는 무관하고, 변경 지점 직전 체크포인트에서 재개한다.

### 대조 실험 (bench2) — 조건 분리

`crates/rdoc-core/src/bin/bench2.rs`(신규)는 같은 700문단 문서를 변형해
게이트 조건을 하나씩 분리한다 (env: `RDOC_BENCH2_LONG`,
`RDOC_BENCH2_TABLES`, `RDOC_BENCH2_HEADING`). 키 입력 mean (ms):

| 변형 | 페이지 | 0.8 | v0.10.1 | 배율 |
|---|---|---|---|---|
| 1줄 문단, 표 0 | 22 | 7 | **4** | **0.57×** |
| 1줄 문단, 표 14 | 23 | 9 | **5** | **0.56×** |
| 4줄 문단, 표 0 | 61 | 31 | 42 | 1.35× |
| 4줄 문단, 표 14 | 63 | 41 | 52 | 1.27× |

- **표는 무관하다** (0/14 어느 쪽이든 같은 방향·비슷한 배율).
- **문단 길이가 부호를 뒤집는다**: 1줄이면 v0.10.1이 **1.8× 빠르고**,
  4줄이면 느려진다. `restart_record_block_is_safe`의
  `paragraph.lines.len() <= 2`와 방향이 일치한다.
- 제목 문단(`Heading1`) 1개 추가는 3→5 ms로 **거의 영향 없었다**.
  기본 스타일 세트에서 `heading_level`이 채워지지 않는 것으로 보이며,
  게이트의 `heading_level.is_none()` 조건은 이 문서에서는 작동하지 않는다.

각주 조건은 `input.footnotes.is_none()`으로 코드에 명시돼 있고, 각주가
생긴 뒤 네이티브 노트 연산이 54~89 ms → 724~1334 ms로 뛰는 관측과
직접 대응한다.

주의(정직한 한계): S3 벤치(`bench`)의 2.4× 배율은 bench2의 같은 형태
문서(4줄 문단 + 표 14, 63페이지)에서 재현되지 않았다(1.27×). 두 벤치의
차이(전 페이지 SVG 렌더 선행 등)까지는 추적하지 않았다. **확정적으로
말할 수 있는 것은 위 매트릭스와 각주 절벽, 그리고 게이트 코드 자체**이며,
"3줄 문단 하나가 2.4× 전부를 설명한다"고까지는 주장하지 않는다.

## 결론

- **이행 재보류.** 기능은 완전 등가이고 포크는 3커밋 더 슬림해지지만,
  실제 Word 문서(머리글/꼬리글이 있거나 3줄 이상 문단이 있는 문서 =
  사실상 전부)에서 타이핑 1.46×·undo 2.15× 회귀.
- 다만 S55와 달리 **방향이 잡혔다**: 적격 판정이 문서 전역 all-or-nothing
  이고, 게이트를 충족하면 v0.10.1이 0.8보다 1.8× 빠르다(bench2). 판정을
  블록/구간 단위로 내리고 문단 줄 수 상한(≤2)과 각주 조건을 완화하면
  이행이 열릴 여지가 크다.
- 프로덕션은 svg-poc-0.8(29a4a5c) 유지. 스파이크는 포크 브랜치
  `svg-poc-0.10`, rdoc 브랜치 `s56-v0101-spike`, 적응 패치
  docs/upstream/2026-08-26-rdoc-v0101-adaptation.diff로 보존.
- `crates/rdoc-core/src/bin/bench2.rs`(게이트 대조 벤치)를 main에 추가.
