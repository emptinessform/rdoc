# 2026-09-06 — S59: 업스트림 v0.12.0 스파이크 (이행 5회째 판정)

## 배경

2026-09-03 업스트림이 **v0.12.0**을 태그했고(`19adaacf`, S64 stable release
review), 열려 있던 이슈 3개를 모두 종결했다.

- **#65** (각주 참조 캐시 무효화) — F-X072, S63에서 이미 해결. v0.12.0 포함.
- **#66** (산문에서 재시작 페이지네이션이 안 켜짐) — F-X073, S63에서 해결.
- **#67** (F-X073이 페이지 넘는 문단에서 이중 페이지네이션 → 2배 회귀)
  — **F-X075**로 해결. v0.12.0 포함.

`v0.12.0:.claude/plans/F-X075-design.md`가 S58 진단을 그대로 인용한다:

> Remove the `Engine::layout_transaction` branch that rejects every recorded
> result with `had_split_paragraph`. ... A document with ordinary four-line
> paragraphs therefore pays for two complete pagination passes after every
> edit and can never reach the restart path F-X073 introduced.

즉 S58에서 `RDOC_NO_SECOND_PASS`로 25~28 → 5~6 ms를 확인했던 그 2차 패스를
업스트림이 제거했고, 안전성은 `Pager::finish_page_before`의 완전 블록 경계
체크포인트로 좁혀서 유지했다.

업스트림 main은 이미 S68(`c8908d07`)까지 갔지만, 이번 스파이크는 **태그가
붙은 v0.12.0만** 대상으로 했다.

## 이번 단계의 목표·범위·검증 기준

- **목표**: F-X073의 2배 회귀가 실제로 사라졌는지, F-X072 이득이 유지되는지
  실측해 5회째 보류인지 이행인지 판정.
- **범위**: 포크 리베이스 → 네이티브 A/B → 브라우저 A/B → 기능 등가.
- **검증 기준**: 병합·undo·타이핑이 v0.8 대비 페어 승패에서 회귀 없음 +
  기능 등가 + 리베이스 적응 비용 감당 가능.

## 1. 포크 리베이스 — 처음으로 포크가 줄었다

`svg-poc-0.8`의 50커밋을 v0.12.0 위로 옮겼다. 처음 시도한 통짜 리베이스는
"충돌은 HEAD 유지"로 풀었더니 **업스트림 구현과 대체된 포크 조각이 뒤섞인
하이브리드**가 되어 rdocx-layout에서만 25개 컴파일 에러가 났다. 폐기하고,
업스트림이 흡수한 커밋은 **부분 적용이 아니라 통째로 드롭**하는 방식으로
다시 했다.

### 유지한 32커밋 + 신규 4커밋

포크는 **50 → 36커밋**(v0.12.0 기준). 체리픽 32건 중 8건이 충돌했고, 신규
커밋 4건이 필요했다:

1. `e2b6ccbd` — `take_layout_engine`/`set_layout_engine`을 업스트림의
   `bundled_fallback_layout_engine` 위에 다시 노출. 업스트림의
   `commit_staged_mutation`은 `pub(crate)`라, 바이트에서 Document를 다시
   만드는 undo 스냅샷 복원 경로가 여전히 공개 API를 필요로 한다.
2. `62acf131` — 리베이스 낙진: 라인브레이커 재구조화된 호출부에
   `default_tab_interval_pt`/`hangul_word_wrap` 배선, `SYNTHETIC_ITALIC_TAN`
   재노출, `HyperlinkSpan`의 `tooltip`/`doc_location`, `TextSegment`의
   `direction`, `FontData`의 `synthetic_italic`, `LineBreakParams`의 신규
   필드 2개(rpptx-render·테스트 포함), `ensure_list_num`의 `num_fmt` 참조 비교.
3. `cda4a8ff` — **`convert::text_segments` 프리스플릿 제거**. 이건 v0.8.0
   업스트림 코드였고 v0.12.0이 없앤 것인데, 리베이스가 포크의 수정본을
   되살려 업스트림 계약 테스트 2개를 깼다
   (`word_projection_leaves_break_segmentation_to_shared_layout`,
   `reported_words_do_not_duplicate_boundary_glyphs`).
   한글 어절 규칙은 프리스플릿 없이도 성립한다 — 프리스플릿이 없으면 모든
   런이 in-segment 스캔을 타므로 `split_text_at_break_opportunities`의
   한글↔한글 억제(이미 `LineBreakParams::hangul_word_wrap`로 배선됨)가
   규칙 전부다.
4. `6d71cb3d` — 위 제거로 쓰이지 않게 된 엔진 로컬 플래그 정리.

부수적으로 `text_extents`(플로트 우회 테스트 헬퍼)를 advance reach가 아니라
**ink reach**로 바꿨다. 후행 공백이 마진 밖으로 걸리도록 한 포크 커밋
`46254633`이 이미 각주 마진 가드에 적용한 것과 같은 규칙이다 — 플로트 옆
줄이 공백만으로 2.1pt 넘어간다.

포크 검증: `cargo check --workspace --all-targets` 클린,
oxml-layout 103 passed, rdocx-layout 229 passed, 0 failed.
rdocx는 325 passed / 5 failed 인데 5건 모두 이 머신의 환경 문제다 —
3건은 `shasum: program not found`(Windows에 shasum 없음), 2건은 POSIX
전용 경로를 쓰는 원자적 저장 테스트의 `InvalidFilename`(OS 123).
리베이스와 무관하다.

## 2. rdoc 적응 비용 — S57/S58의 "0줄"과 다르다

S57은 충돌 5건·적응 0줄, S58은 충돌 0건·적응 0줄이었다. v0.12.0은 **처음으로
rdoc 소스를 실제로 고쳐야 했다.**

### (a) 호출부 이름 3곳 (사소)

`layout_with_fonts_aliases_options_and_bundled_fallback` →
업스트림 `layout_with_fonts_aliases_and_bundled_fallback_and_options`.
인자 순서 동일.

### (b) `PositionedElement::MarkedContent` — 전 페이지 백지 (해결함)

v0.12.0은 모든 요소를 태그드 구조 컨테이너로 감싼다. rdoc의 요소 순회 3곳
(`SvgRenderer::emit_elements`, `collect_hits`, `hash_elements`)이 이 변형을
모르고 통과시켜, **레이아웃은 정상인데 모든 페이지가 빈 SVG(215바이트),
히트 0개**로 나왔다. 세 곳 모두 children으로 내려가게 고쳤다.

고친 뒤 네이티브 PoC가 v0.8 핀과 동일: 2페이지, 167 KB + 12 KB SVG,
히트 272개(매핑 264 / 미매핑 8).

### (c) `PositionedElement::MultilingualText` — **미해결, 남은 작업**

v0.12.0은 문단이 다음 중 하나면 문단 전체를 다국어 셰이핑 경로로 보내고
`MultilingualGlyphRun`을 내보낸다 (`engine.rs:5448`):

- 문단 base direction이 `Auto`가 아니거나,
- 런 중 하나라도 direction이 `Auto`가 아니거나,
- 텍스트에 CJK 표의문자(U+3400–9FFF, **한자 포함**), 가나(U+3000–30FF),
  태국어, 데바나가리, 히브리/아랍 문자가 있으면.

**한글(U+AC00–D7AF)은 트리거 목록에 없다** — 순한글 텍스트는 그대로 `Text`다.
그래서 데모 문서·bench.docx(한글+라틴)는 영향이 없고, 브라우저 배터리
50/50도 통과한다.

하지만 rdoc의 SVG 렌더러·히트 매핑은 `GlyphRun`만 안다. 코퍼스 14개 중 7개가
런을 잃었다:

| 문서 | v0.8 runs | v0.12 runs | 트리거 |
|---|---|---|---|
| comment | 7 | 0 | direction (본문에 CJK 없음) |
| font | 16 | 1 | こんにちは, 世界 |
| header_footer | 5 | 1 | direction |
| highlight_and_underline | 5 | 0 | マーカー, 下線 |
| history_libre_office | 3 | 0 | direction |
| image | 1 | 0 | direction |
| table_libre_office | 5 | 1 | direction |

주의: 7개 중 5개는 본문에 트리거 문자가 **없는데도** 다국어 경로를 탄다 —
LibreOffice가 방향 속성을 붙여 내보내기 때문이다. 즉 노출 범위가 "한자 혼용
문서"보다 훨씬 넓다. **`MultilingualGlyphRun` 렌더·히트 지원이 이행의
전제 조건**이다(대략 렌더러 + push_hit 경로 100~200줄 추정).

## 5. 기능 등가

- 브라우저 배터리 **50 PASS / 0 FAIL**
- 코퍼스 14파일 0 failure — 단 위 §2(c)대로 7개 문서가 런을 잃음
  (status는 ok지만 실제로는 백지)
- 네이티브 PoC: 2페이지, 167+12 KB SVG, 히트 272(264 매핑) — v0.8과 동일
- 브라우저: 58페이지, `2/58 pages redrawn` 델타 — v0.8과 동일
- wasm 크기 **12.29 → 17.53 MB (+43%)** (S58의 17.5 MB와 같은 수준)

## 판정

| 항목 | S58 (v0.11.1+S63) | S59 (v0.12.0) |
|---|---|---|
| 타이핑 | 1.24× 회귀 | 해소 (1.04× ~ 1.6× 개선) |
| 병합 | 1.53× 회귀 | 동률 |
| undo | 1.39× 회귀 | 동률 |
| 로드 | 1.54× 회귀 | 동률 |
| **Enter** | 0.83× (1/5) | **2.32× 회귀 (5/5)** |
| 각주 삽입/삭제 | (미측정) | **4× 회귀 (4/4)** |
| 포크 커밋 | 50 (하나도 못 줄임) | **36 (18 드롭)** |
| rdoc 적응 | 0줄 | 렌더러 3곳 + MultilingualText 미구현 |
| wasm | 17.5 MB | 17.53 MB |

**성능 관점에서는 v0.11.1/S63과 비교가 안 될 만큼 좋아졌다.** 네 번의 보류를
만든 회귀 3개(타이핑·병합·undo)가 모두 사라졌고, 타이핑은 네이티브에서
2.4배 빨라졌으며, 포크가 14커밋 줄었다.

**하지만 이행을 지금 확정하지 못하는 이유가 둘 있다:**

1. **`MultilingualText` 미지원** — LibreOffice가 만든 평범한 문서 상당수가
   백지로 렌더된다. 이건 성능이 아니라 기능 결손이고, rdoc 쪽 작업이다.
2. **Enter 2.3× / 각주 4× 회귀** — 구조 편집 경로가 v0.8보다 확실히 느리다.
   S58에서 F-X073이 만든 이중 페이지네이션과는 다른 원인(재시작 레코드
   재발행 비용)으로 보이며, 업스트림 판단 영역이다.
