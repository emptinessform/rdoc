# 2026-08-22 — S3-②③④: 델타 렌더링 + 지속 엔진 + 문단 블록 캐시

승인된 순서(④→②)대로 진행. 기준선: 63페이지, 키 입력당 네이티브 1,144ms /
wasm ~590ms. 게이트 <30ms.

## ④ 델타 렌더링 (rdocx-svg-poc, 커밋 "S3-2")

- 히트맵 수집을 SVG 생성에서 분리 (`collect_hits` — 텍스트 워크만).
- 페이지 구조 해시를 SVG 생성 **전에** 계산 → 변경 페이지만 SVG 생성·전송·
  DOM 교체. per-page defs + `pg{N}-` 접두사로 DOM id 충돌 제거,
  HitRun id 페이지-로컬화, JS 선택 모델 (page, idx) 재작성.
- wasm 델타 JSON: `{total, pages:[[i,svg]], hits:[[i,runs]]}` —
  문단 인덱스만 밀리는 편집(Enter)을 위해 SVG/히트 해시 분리.
- 실측: wasm ~590 → 323~410ms, "1/63 pages redrawn".

## ② 지속 레이아웃 세션 (포크 rev 6a0b151)

계측(RDOCX_TIMING) 결과 → 순차 공략:
- `build_input` 1~3ms, `engine.layout` ~150ms (blocks ~100 / paginate ~19 / 기타 ~45).
- **FontManager.shape_memo**: (font id, text+size 해시)→ShapedText 메모.
- **Engine 재사용**: 추가 폰트 지문 가드(재로딩 방지), `rdocx::Document`가
  엔진을 보유해 편집을 넘어 캐시 생존 (wasm의 13MB 주입 폰트 복사 제거).
- **문단 블록 캐시**: 문단 XML+폭+revision view+폰트셋 지문 → ParagraphBlock.
  **마커(번호/불릿) 있는 문단은 캐시 제외**로 NumberingState 정합 보존.
  blocks 100→32ms (잔여는 Debug 포맷 지문 비용 + 번호 문단 + 표).
- 함정: 계측용 `Instant::now()`가 wasm32에서 패닉 → cfg 게이트.

## 지문 전용 워커 + FontData 공유 (S3-5, 포크 rev bd26eda)

포크 커밋 bd26eda("Share FontData bytes, fast paragraph fingerprint,
engine handoff APIs")에 함께 구현·푸시됨 (중단 전 세션):

- **지문 전용 워커** (`fingerprint_paragraph`, engine.rs): 블록 캐시 키를
  `format!("{para:?}")` 전체 해시 대신 전용 워커로 — 런 텍스트는 raw bytes
  (preserve_space 포함), 문단/런 속성과 비텍스트 런·하이퍼링크/코멘트/북마크/
  컨트롤/리비전 프로젝션은 작은 구조라 Debug 경유 유지. CT_P에 레이아웃
  관련 필드가 추가되면 워커도 갱신 필요 (주석에 명시).
- **FontData.data → `Arc<Vec<u8>>`**: LayoutResult 생성 시 로드된 전체 페이스
  (~50MB, CJK 폴백 포함) 복사 제거 — font_data 39~52ms → 0ms. pre-1.0 타입
  브레이크.

실측 (63페이지, `cargo run --release --bin bench`, RDOCX_TIMING):

- 키 입력당 재조판: 101ms → **평균 37~38ms (min 33)**.
- 분해: blocks 16~20 (기존 32) + paginate 12~15 + post 1 + font_data 0
  (기존 "엔진 후처리 ~45ms"가 폰트 복사였음 — Arc 공유로 소멸).
- wasm 브라우저: 타이핑 64~103ms (S3-4 표의 "이월 후" 열이 본 rev 실측).

게이트 <30ms까지 잔여: blocks의 번호 문단·표(캐시 제외분) + paginate.

## undo/redo 엔진 이월 (S3-4, 포크 rev bd26eda)

"undo/redo는 Document 재생성이라 엔진 캐시가 식음" 항목 해결:

- 포크에 `Document::take_layout_engine()` / `set_layout_engine()` 공개
  (crates/rdocx/src/document.rs:616,624, svg-poc 브랜치 bd26eda — 푸시 완료).
- wasm.rs `replace_doc()`: undo/redo에서 복원된 Document로 교체할 때 기존
  엔진(shape_memo + 문단 블록 캐시 포함)을 새 Document로 이월.

실측 (63페이지 bench.docx, 헤드리스 브라우저, 콜드 로드 후 각 3회):

| 조작 | 이월 전 | 이월 후 |
|---|---|---|
| 타이핑 | 126~152ms | 64~103ms |
| undo | 150~266ms | 75~91ms |
| redo | 217~302ms | 82~126ms |

undo/redo가 타이핑과 같은 수준으로 수렴 (이전엔 ~2배). 델타 렌더링은
"1/63 pages redrawn" 유지. 검증: 네이티브 테스트 7/7, 코퍼스 14/14,
wasm 빌드·에디터 루프(타이핑/undo/redo) 정상.

## 재시작 가능한 페이지네이션 + 표 블록 캐시 (S3-6, 포크 rev 5c4dd70)

키 입력당 63페이지 전체 재페이지네이션(12~15ms)을 증분화. **게이트 <30ms 달성**.

설계 (포크 `rdocx-layout/paginator.rs` + `engine.rs`):

- **체크포인트**: 블록이 새 페이지를 깨끗하게 시작하는 지점(문단 분할 걸침·
  각주 이월·float 없음)을 기록. 루프 톱이 아니라 **블록 배치 진입점**
  (문단 배치 함수 입구, 표 arm)에서 잡아야 실제로 잡힘 — 페이지 경계는
  거의 항상 "문단이 안 맞아 옮겨질 때" 생기기 때문.
- **프리픽스 재사용**: 블록 지문(소스 워크 + 렌더된 번호/각주 마커 salt —
  교차 블록 상태를 정체성에 포함)의 최장 공통 프리픽스로 분기점을 찾고,
  keep-with-next 1블록 룩어헤드 때문에 한 경계 뒤에서 재개.
- **서픽스 재접합**: 재개 패스가 "끝에서부터 오프셋 일치 + 페이지 번호 동일"
  경계에 도달하면 이전 꼬리 페이지를 그대로 접합.
- **폴백(전체 실행)**: 다중 섹션, floating drawing 존재(뒷 블록이 앞 페이지에
  그림을 얹을 수 있음), 환경 변화(sectPr/머리글·꼬리글/각주 파트/폰트/리비전 뷰),
  유효 체크포인트 없음.
- **`LayoutResult.pages` → `Vec<Arc<PageFrame>>`** (pre-1.0 타입 브레이크,
  FontData와 동형): 페이지 재사용이 깊은 복사(~12ms/회)가 아닌 포인터 복사가
  되도록. 필드 치환은 필드가 있는 페이지만 unshare.
- **표 블록 캐시**: 전용 소스 워커(`fingerprint_table`) 키. 번호 마커/각주
  참조를 렌더하는 표는 제외 (NumberingState/각주 순서 정합).

실측 (63페이지 bench, git rev 5c4dd70 빌드):

| 항목 | 이전 | 이후 |
|---|---|---|
| paginate | 12~15ms | **1~3ms** ("29 prefix + 4 rebuilt + 30 spliced") |
| 키 입력당 전체 | 37~38ms | **평균 24~30ms (min 23)** |

검증: **동등성 테스트 8건 신설** — 캐시 경로 결과가 신규 엔진 전체 계산과
바이트 단위 동일함을 강제 (꼬리/중간/1페이지 편집, 삽입/삭제, 무편집,
헤딩 페이지 이동, 다중 섹션 우회, 각주 정의 무효화). rdocx-layout 119,
oxml-layout 62, 워크스페이스 전체에서 클린 기준선 대비 **신규 실패 0**
(이 머신의 기존 픽스처 의존 실패 26건은 변경 전후 동일 — 이번에 전 워크
스페이스를 처음 돌려 발견, 기존 3건의 상위집합). 우리 테스트 7/7, 코퍼스
14/14, wasm 빌드·에디터 루프 정상, 델타 "1/63 pages redrawn" 유지.
wasm 브라우저는 머신 부하로 편차 큼(72~160ms) — 이제 렌더+DOM 지배.

알려진 한계 (기록):

- 함께 발견한 기존 문제: S3-3 문단 블록 캐시는 각주 *참조 마커* 번호가
  앞쪽 각주 삽입으로 밀리는 경우를 지문에 못 잡음 (현 에디터는 각주 편집
  없음; 업스트림 기여 시 명시 예정).
- 스타일·넘버링 *정의* 변경은 여전히 미지문 (블록 캐시의 문서화된 한계와
  동일 규칙).
- oxml-pdf 단위테스트의 FontData Arc 컴파일 깨짐(bd26eda 잔재)도 함께 수정.

  필드는 의도적으로 비귀속. 0.4.0 인큐베이팅 → 0.8.0 안정.
