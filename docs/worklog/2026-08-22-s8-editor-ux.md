# 2026-08-22 — S8-1: 에디터 UX 마감 3종

JS 전용 (wasm/포크 무변경). 편집 루프의 사용자 관점 완결.

## 구현

1. **Save .docx 버튼**: `save_docx()`(현재 문서 직렬화)를 Blob 다운로드로
   연결 — 지금까지 편집 결과를 파일로 가져갈 UI가 없었음.
2. **방향키 ↑/↓**: 캐럿의 시각 위치(x, baseline)에서 해당 방향의 가장
   가까운 베이스라인을 찾고 그 줄에서 x가 가장 가까운 히트로 이동
   (`moveCaretLine`). 줄 간·문단 간·(준비만) 페이지 간. 편집 가능
   경로만 대상.
3. **캐럿 자동 스크롤**: drawCaret 후 microtask에서 캐럿 rect가 뷰포트
   (헤더 70px 고려) 밖이면 중앙으로 scrollBy. SVG 자식이라
   scrollIntoView가 불안정해 명시 스크롤 사용.

## 검증 (헤드리스, 전부 통과)

- Save 버튼 존재 + save_docx 바이트(4,938) 생성.
- ArrowDown: d/4→d/5로 다음 줄 이동(baseline y 증가), ArrowUp 원위치
  (±2pt), 15회 연속 하강 워크 10줄 이상 진행.
- 워크 후 캐럿 rect가 뷰포트 내 (598/720) — 자동 스크롤 동작.
- 이동 후 타이핑 정상. IME/분할/왕복 회귀 그린.
- 테스트 함정 하나: 스크롤은 microtask라 동기 검사에선 미실행 —
  테스트에 대기 삽입 (앱 결함 아님).

## S8-2: 키보드/마우스 기본기 마감 (JS 전용)

- **Delete**(전방 삭제): 캐럿 위치의 글자 삭제, 오프셋 유지; 문단 끝에선
  조용한 no-op (전방 병합은 후속).
- **Home/End**: 캐럿의 시각적 줄 기준 — 같은 문단·같은 베이스라인
  히트들의 최소/최대 오프셋으로.
- **Ctrl+A**: 전체 선택 (표시·복사용; 범위 편집은 양끝 호환일 때만).
- **더블클릭 단어 선택**: 문단 텍스트에서 공백 경계로 확장, 히트 참조
  선택으로 표현 — 대치 후 undo 1회.
- 검증 (전부 통과): forward delete 정확성+오프셋 유지, 문단 끝 no-op,
  End→18(문단 끝)/Home 복귀, Ctrl+A 복사 785자, 더블클릭 "각주가" 선택
  + "W" 대치 + undo 1회. UX1/IME/분할 회귀 그린.
