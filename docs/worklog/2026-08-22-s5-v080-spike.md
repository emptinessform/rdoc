# 2026-08-22 — S5-1: 업스트림 v0.8.0 이행 스파이크

브랜치 `spike/v0.8.0`. 목표: 포크 없이(또는 최소 포크로) 업스트림 v0.8.0에
직결했을 때의 기능 정합과 성능을 실측.

## 결과: 최소 포크 3커밋으로 완전 동작

포크 `svg-poc-0.8` (v0.8.0 기반, 02b2252):

1. `paragraph_body_index` + `Paragraph::split_run` (S2 편집 헬퍼 58줄 —
   비공개 필드 접근 필요라 이식 불가, 기존 dec7d54 체리픽)
2. `set_footer_page_number` (bench HF 변형용)
3. **caller-fonts 경로 번들 폴백** — `Engine::new_with_caller_fonts`가
   주입 폰트만으로 DB를 구성해 Calibri 미해결 (`font not found`).
   deterministic(번들) 엔진 기반으로 교체, 주입 폰트는
   `load_additional_fonts`로 우선순위 유지. 업스트림 후속 후보.

이전 포크가 갖고 있던 layout()/layout_with_fonts 패치와 S3 캐시 4종은
전부 공식 API(F-X032)·F-X038로 대체됨. poc 쪽 변경은
`WordLayoutResult.layout` 필드 경유(±10줄)와 undo 엔진 이월 제거
(공개 핸드오프 API 없음 — 세션/핸들 설계 리뷰 대기).

## 기능 정합 (전부 통과)

- 네이티브 테스트 7/7, 코퍼스 14/14
- wasm 빌드, 에디터 루프 + IME 7시나리오 그린, 델타 "1/63 pages redrawn"

## 성능 (63페이지 bench)

| 경로 | 우리 포크(pre-0.8.0 + S3~S3-7) | 순정 v0.8.0 (F-X038만) |
|---|---|---|
| 네이티브 키 입력당 | 24~30ms | **160ms** (HF 181ms) |
| wasm 키 입력당 | 72~84ms | **200~282ms** |

- F-X038만으로 1,144→160ms. 잔여 6배 격차가 우리의 미기여 레이어 몫:
  재시작 페이지네이션(+표/HF 캐시+치환 재사용) 및 FontData 공유.
- wasm이 특히 나쁜 이유: caller-fonts 경로가 **매 호출 새 엔진** —
  셰이핑 메모·문단 캐시가 키마다 콜드, 주입 폰트(13MB)도 매번 재로드.
  업스트림 세션/핸들 설계 논의와 정확히 맞물리는 지점.

## S5-2: 성능 레이어 이식 (포크 svg-poc-0.8 @ dec510a)

업스트림 리뷰 경계(F-X039/F-X040)에 맞춘 분리 커밋으로 이식 완료:

- `d5d5fa1` 번들 폴백을 별도 진입점으로 (기존 caller-fonts 격리 계약
  테스트를 스파이크 패치가 깨고 있던 것을 발견·수정)
- `d211103` FontData.data → `Arc<[u8]>` (F-X039)
- `31498a2` LayoutResult.pages → `Vec<Arc<PageFrame>>` (F-X039);
  canonicalize_layout_fonts는 remap이 항등이면 페이지 공유 유지
- `35ebeb9` 재시작 페이지네이션 + 표/HF 캐시 + 치환 재사용 (F-X040).
  **v0.8.0 계약 적응**: 스타일·테마는 F-X038 컨텍스트 게이트로, 넘버링·
  각주·헤더 파트·sectPr·폰트 세대·리비전·**F-X037 소스 노드 테이블**을
  페이지네이션 환경 지문에 포함 (재사용 페이지에 SourceSpan이 구워져
  있어 문단 삽입/삭제는 전체 폴백). 표/HF 캐시는 F-X038과 동일하게
  진단·폰트 트레이스 리플레이. 동등성/무효화 테스트 16건
  (provenance 동등성, 문단 수 변화, 스타일 정의 변경 포함) 전부 통과,
  rdocx-layout 147/147, 워크스페이스 스윕 실패 0.
- `00784a1` 번들 폴백 경로 엔진을 Document에 유지 + take/set 핸드오프
  (F-X039 세션 설계 전 임시 형태) — wasm undo 캐시 생존.
- `14255da`+`dec510a` F-X038 문단 캐시 튜닝: 지문 프리필터(타입 키가
  최종 판정 — 충돌 안전 유지), 캡 256→4096 (700문단 문서 스래싱 해소),
  히트 시 O(n) LRU 이동 제거.

실측 (63페이지; 오늘 머신 부하로 편차 큼 — 아래는 관측 최선치):

| 단계 | 키 입력당 |
|---|---|
| 순정 v0.8.0 | 160ms |
| + 이식 (paginate+post 2~3ms 달성) | 95ms |
| + 문단 캐시 튜닝 | **63ms (min 58)** |
| (구 포크 참고치) | 24~30ms |

잔여 병목은 blocks 단계의 F-X038 파이프라인 고정비용 (문단당
cache-safe 검사(스타일 해석 포함), 히트당 블록 딥클론, fp 계산 등) —
조용한 머신에서 프로파일 후 추가 튜닝이 다음 항목. wasm: 타이핑
202~241ms, undo 141~155ms (엔진 이월 동작 확인), 델타 "1/63" 유지,
기능 스위트 그린.
