# 2026-08-22 — S5-1: 업스트림 v0.8.0 이행 스파이크

브랜치 `spike/v0.8.0`. 목표: 포크 없이(또는 최소 포크로) 업스트림 v0.8.0에
직결했을 때의 기능 정합과 성능을 실측.

## 결과: 최소 포크 3커밋으로 완전 동작

포크 `svg-poc-0.8` (v0.8.0 기반, 02b2252):

1. `paragraph_body_index` + `Paragraph::split_run` (S2 편집 헬퍼 58줄 —
   비공개 필드 접근 필요라 이식 불가, 기존 dec7d54 체리픽)
2. `set_footer_page_number` (bench HF 변형용)
3. **caller-fonts 경로 번들 폴백** — `Engine::new_with_caller_fonts`가
   주입 폰트만으로 DB를 구성해 Calibri 미해결 (`font not found`).
   deterministic(번들) 엔진 기반으로 교체, 주입 폰트는
   `load_additional_fonts`로 우선순위 유지. 업스트림 후속 후보.

이전 포크가 갖고 있던 layout()/layout_with_fonts 패치와 S3 캐시 4종은
전부 공식 API(F-X032)·F-X038로 대체됨. poc 쪽 변경은
`WordLayoutResult.layout` 필드 경유(±10줄)와 undo 엔진 이월 제거
(공개 핸드오프 API 없음 — 세션/핸들 설계 리뷰 대기).

## 기능 정합 (전부 통과)

- 네이티브 테스트 7/7, 코퍼스 14/14
- wasm 빌드, 에디터 루프 + IME 7시나리오 그린, 델타 "1/63 pages redrawn"

## 성능 (63페이지 bench)

| 경로 | 우리 포크(pre-0.8.0 + S3~S3-7) | 순정 v0.8.0 (F-X038만) |
|---|---|---|
| 네이티브 키 입력당 | 24~30ms | **160ms** (HF 181ms) |
| wasm 키 입력당 | 72~84ms | **200~282ms** |

- F-X038만으로 1,144→160ms. 잔여 6배 격차가 우리의 미기여 레이어 몫:
  재시작 페이지네이션(+표/HF 캐시+치환 재사용) 및 FontData 공유.
- wasm이 특히 나쁜 이유: caller-fonts 경로가 **매 호출 새 엔진** —
  셰이핑 메모·문단 캐시가 키마다 콜드, 주입 폰트(13MB)도 매번 재로드.
  업스트림 세션/핸들 설계 논의와 정확히 맞물리는 지점.

## 판단 재료

  넘버링 지문 포함) 반영해 이식 → 그 산출물이 곧 업스트림 분리 이슈/PR
  재료 → 이식 완료 후 main 전환.
- 업스트림 보고 가치 2건 발견: caller-fonts 번들 폴백 부재, caller-fonts
  엔진 비유지(wasm 에디터 시나리오).
