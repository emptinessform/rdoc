# 2026-08-22 — S20-1: 실문서 진단·수정 — 병원 진료비 영수증

## 발단

사용자 실문서(분당제생병원 진료비영수증 .docx)가 참조 PDF(1페이지 밀집
양식)와 달리 4페이지에 걸쳐 표 없이 텍스트만 흘러내림. wasm·네이티브·
업스트림 PNG 백엔드 모두 동일 → rdocx-layout 문제로 확정.

## 문서 구조

최상위 표 1개 안에 표 6개 중첩(깊이 2), gridSpan 135회, vMerge 59회,
`trHeight hRule="exact"` 44행, 표 스타일 "aa"(Table Grid — 테두리·
spacing after=0을 스타일이 보유), 플로팅 도장/워터마크 4점(behindDoc
포함, 1점은 EMF).

4. **표 스타일 미캐스케이드**: 스타일 파서가 `<w:tblPr>`을 통째로

추가 지적 2건 (사용자 피드백)으로 2건 더:

7. **"항목별 설명" 박스 위 테두리 소실**: 첫 행 셀들이

9. **behindDoc 레이어링** (사용자 피드백): 셀 앵커 이미지를 자기 셀
   텍스트 앞에만 끼워 넣어, 먼저 그려진 이웃 셀 내용 **위**에 올라탔음
   → behindDoc 드로잉은 render_table_row를 관통하는 behind 싱크로
   페이지 배경 레이어에 합성(본문 워터마크와 동일 경로), 전경 앵커

10. **빈 셀 입력 시 기본 폰트** (사용자 피드백): 빈 문단에 새 런을

   확인.

### "항목별 설명" 박스 위 테두리 — 스펙 vs Word 실동작

첫 행 셀들은 `<w:top w:val="nil"/>`를 선언한다. ECMA-376 문언대로면
nil은 "이 셀의 이 변에는 테두리 없음 — 표 수준 테두리도 무시"라서
**선이 안 나오는 게 맞다**. 그런데 MS Word는 **표의 바깥 경계**에서는
셀 nil보다 표 수준(스타일 포함) 테두리를 우선해 윤곽선을 그린다 —
참조 PDF의 선이 그 결과다. 즉 스펙 문언과 Word 구현이 갈리는 지점이고,
문서 저자는 Word 화면을 보고 만들었으므로 우리는 Word 실동작을 따랐다:
바깥 경계(첫/마지막 행·열)에서만 nil→표 테두리 폴백, 셀 사이 경계는
스펙대로 억제 유지.
