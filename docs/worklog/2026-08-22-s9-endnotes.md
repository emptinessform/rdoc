# 2026-08-22 — S9-1: 미주 타입 필드 승격

## 목표·범위

포크에서 미주(endnotes)를 각주와 동일한 타입 필드로 승격하고, 그 위에서
미주 분할/병합을 활성화한다. 범위: 포크 `Document` 필드 3종
(`endnotes`/`endnotes_part_name`/`endnotes_dirty`) + open/save/layout 경로,
편집 API 타입 필드 전환, `add_endnote`/`add_endnote_ref` 신설, rdoc 데모에
미주 문장 추가, wasm 미주 split/merge 라우팅. 미주 삽입/삭제 UI(Ctrl+Alt
계열)는 다음 단계.

## 구현 (포크 svg-poc-0.8 → 1652b22)

- `Document`에 타입 미주 필드 승격 — 각주와 완전 대칭:
  - open: `rel_types::ENDNOTES` 파트를 `CT_Footnotes`로 파싱해 필드에 적재.
  - layout: `build_layout_input`이 필드가 비어 있지 않으면 파트 대신 필드를
    사용 (미저장 편집이 즉시 화면에 보임 — 각주에서 고쳤던 결함이 미주에는
    처음부터 없음).
  - save: `endnotes_dirty`일 때만 `to_xml_endnotes()`로 파트 갱신 + content
    type/relationship 보장. 편집 없으면 원본 파트 바이트 보존.
- `with_endnote_paragraph_mut`/`endnote_paragraph_text`: 파트
  파싱-편집-직렬화 왕복 제거, 각주와 같은 in-place 편집으로 교체.
- `split_endnote_paragraph`/`merge_endnote_paragraph` 신설 (각주판 미러).
- `add_endnote(text) -> i32` + `Paragraph::add_endnote_ref(id)` 신설.
- rdoc: 데모에 미주 문장 추가(`en/2/0`), wasm split/merge의
  `is_footnote: false` 거절 분기를 실제 구현 호출로 교체, `__t.hits(page)`
  테스트 훅 추가. Cargo.toml rev 1652b22 고정.

  편집·분할·병합·미저장 레이아웃 가시성·바이트 왕복. 전체 스위트 152
  passed / 3 failed — 실패 3건은 `shasum` 부재로 깨지는 기존 Word 픽스처
  테스트(이 변경과 무관, 변경 전에도 동일).

  `{"ok":true, enPath:"en/2/0", split:{p0:"…보세", p1:"요."}, roundtrip:{edited==after}}`
  — 타이핑/undo, Enter 분할(꼬리 합치면 원문), Backspace 병합, .docx 저장

- 증거: `docs/evidence/s9-endnote-edit.png` — 본문 미주 마커(²), 문서 끝

## 배운 것

- wasm-bindgen `Option<String>`의 `None`은 JS에서 `null`이 아니라
  `undefined` — 테스트 비교는 `== null`(느슨한 비교)로. en-test 첫 실행의
  유일한 실패가 이 테스트 버그였음.
- knowledge.html 덧붙임 3(승격 = 데이터 지위 변화, 진실의 원천 규칙 3가지)
  추가.
