## 5. 원인 규명 (systematic-debugging)

진단 브랜치 `exp/s63-diag` (`6232c06`, RDOC_DIAG 구간 타이머 +
RDOC_NO_SECOND_PASS 오버라이드).

### 구간 분해 — 페이지네이션이다

4줄 × 175문단, 타건 1회:

```
[phase] blocks+notes   1.0 ms   (문단 캐시 hits 174, builds 1 — 정상)
[phase] eligibility    1.3 ms
[phase] pagination    26.7 ms   ← 여기
[phase] post-pag.     27.7 ms
```

문단 캐시는 완벽히 듣는다 (#65 수정 확인). 비용은 전부 페이지네이션.

### 원인 — 폐기되는 2차 페이지네이션

F-X073이 `engine.rs`에 넣은 분기:

```rust
if recorded.had_split_paragraph {
    restart_record_eligible = false;
    let (mut pages, outlines) = paginator::paginate_shared_sections(...);  // 전면 재실행
```

재시작 적격 문서는 먼저 **기록 패스**를 돌린다. 그 패스가
`had_split_paragraph`(문단이 페이지 경계를 넘음)를 보고하면 결과를
버리고 페이지네이션을 **통째로 다시** 돌린다. 산문은 문단이 페이지를
넘는 것이 정상이므로:

- 매 레이아웃마다 페이지네이션을 두 번 한다.
- `restart_record_eligible = false`가 되어 **재시작 레코드가 영영
  발행되지 않는다** (`restart_cache` 0바이트 고정).

같은 문서를 1줄 문단으로 만들면 분할이 없어 기록 패스가 살아남고,
체크포인트에서 **1페이지만** 다시 그리며 2.3 MB 레코드를 발행한다 —
페이지네이션 0.3 ms. 즉 F-X073은 분할 없는 문서에서만 작동한다.

```
[diag] 4줄: restart_eligible=true had_split_paragraph=true  → 재페이지네이션, restart_cache=0
[diag] 1줄: restart_eligible=true had_split_paragraph=false → pages=1 재사용, fits=true 2.3 MB 발행
```

### 비용 상한

`RDOC_NO_SECOND_PASS=1`(기록 패스를 살리고 레코드를 발행)로 재면
4줄 × 175문단이 **25~28 → 5~6 ms**로, v0.8의 11 ms보다도 빠르다.

다만 이것은 해법이 아니다 — 그 상태에서
`unsafe_pagination_state_falls_back_to_full_layout`이 실패한다.
2차 패스는 실제로 무언가를 지키고 있고, 어떻게 고칠지는 업스트림
판단 영역이다.

**#66은 "산문에서 재시작이 안 켜진다"는 이슈였는데, 수정 후에도
산문에서는 여전히 안 켜지고 비용만 2배 붙었다.**

## 판정: 이행 보류 (4회 연속)

**얻는 것**

- F-X072로 각주 절벽 해소 (22 → 7.5 ms). 단, **0.8 핀에는 그 절벽이
  애초에 없으므로 이행해야 얻는 이득이 아니다.**
- 포크 리베이스가 충돌 0건으로 쉬워졌다 (S57은 5건).
- 포크 커밋은 여전히 하나도 못 줄인다 (31커밋 그대로 + 낙진 1건 추가).

**치르는 것**

- 병합 1.53×, undo 1.39× (각 5/5 페어) — **S57에 없던 새 회귀**
- 타이핑 1.24× (5/5), 로드 1.54×, wasm 12.3 → 17.5 MB
- 네이티브 4줄 문단 2.95×, 브라우저 경로 2.50×

기능은 완전 등가(배터리 50/50, 코퍼스 14/14, 히트 272, 58p)이지만,
S57 대비 **회귀가 늘었다**. F-X072는 순이득이고 F-X073은 순손해인데
둘은 같은 main에 있으므로 부분 채택은 rdoc의 선택지가 아니다.

프로덕션 핀은 `29a4a5c`(svg-poc-0.8) 유지.
