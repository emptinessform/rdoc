# 2026-08-22 — S4-1: IME 조합 입력 처리

백로그 "IME 조합 입력 미처리 (완성 문자열 삽입만 검증됨)" 해소. 포크 변경
없음 — rdoc의 wasm.rs + web/index.html만.

## 구현

기존에 compositionstart/update/end → `replace_range` 배선은 있었으나
(중간 상태 표시 자체는 동작), 다음이 빠져 있었다:

- **undo 그룹화**: 조합 업데이트마다 `mutate()`가 체크포인트를 쌓아
  ㅎ→하→한 = undo 3엔트리. →
  `begin_composition()`(체크포인트 1회 + composing 플래그) /
  `end_composition()`(플래그 해제; 문서가 체크포인트와 동일하면 —
  조합 취소 — 엔트리 드롭). composing 중 `mutate()`는 체크포인트 생략,
  실패 롤백도 체크포인트를 쌓은 경우에만 pop. undo/redo/load는 플래그 리셋.
- **선택 상태에서 조합 시작**: compositionstart에서 `begin_composition()`
  후 선택 삭제 → 선택 제거 + 조합 결과가 **한 undo 단위**.
- **조합 중 클릭/드래그**: `finalizeComposition()` — 화면의 프리에딧을
  확정하고 undo 단위를 닫은 뒤 ime input을 blur (OS 조합 리셋).
  clickAt·mousedown 경로에 연결.
- keydown의 `e.isComposing` 가드는 기존에 이미 있었음.
- 테스트 훅 `__t.imeStart/imeUpdate/imeEnd` 추가 (이벤트 사이 상태 검사용;
  기존 simIme는 유지).

키 입력당 조합 업데이트가 전체 재조판을 유발하지만 S3 성능 작업(캐시·증분
페이지네이션·델타 렌더링) 덕에 실시간 표시가 실용적임 — 이 단계가 S3 뒤에
온 이유.

## 검증 (헤드리스 브라우저, demo.docx, 7개 시나리오 전부 통과)

1. 단계별 조합: ㅂ 표시 → 바로 교체 → 박 확정 (중간 상태가 화면 텍스트에
   실재함을 이벤트 사이에 검사).
2. undo 1회로 음절 전체 제거, redo로 복원.
3. 다음절 연속 조합 (한+글 = simIme 2회) → "한글", undo 2회로 원복.
4. 조합 취소 (compositionend ""): 텍스트 원복 + undo 스택 무오염
   (직전 편집 "x"가 다음 undo로 제거됨을 확인).
5. 조합 중 클릭: 프리에딧 확정 유지, undo 1회로 제거.
6. 선택 → 조합: 선택 대치, undo 1회로 원복.
7. 일반 편집(타이핑/백스페이스/Enter/undo) 회귀 없음.

네이티브 테스트 7/7. 결과 JSON: `{"ok":true,"fails":[]}`.

## 남은 한계 (백로그)

- 프리에딧 밑줄 등 시각 구분 없음 (일반 텍스트로 표시).
- 실제 OS IME(Windows 한글 IME)로의 수동 확인은 헤드리스로 대체 —
  CompositionEvent 시퀀스는 표준이지만 IME별 이벤트 순서 편차(예: end 직후
  start, update 없이 end)는 실기기 확인이 이상적.
- 조합 중 Esc 취소는 IME가 compositionend("")를 보내는 경로로 커버.
