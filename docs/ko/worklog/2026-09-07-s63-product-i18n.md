# 2026-09-07 — S63: 제품 UI 다국어화

S62가 문서를 한/영 2본으로 만들었으니, 이번에는 제품이다. UI 문자열을
소스에서 걷어내 로케일 테이블로 모으고, 언어를 실행 중에 바꿀 수 있게 했다.

## 1. 구조

```
web/src/i18n/
  index.ts   78줄 — 로케일 결정, t(), applyI18n()
  ko.ts     213줄 — 187개 키
  en.ts     211줄 — 같은 키 집합
  boot.ts    12줄 — wasm 부팅보다 먼저 UI를 칠하고 선택기를 연결
```

- **로케일 결정 순서**: `?lang=` → `localStorage("rdoc.lang")` →
  `navigator.language`. 한국어면 ko, 아니면 en.
- **폴백**: `TABLES[locale][key] ?? ko[key] ?? key`. 영문 테이블에 구멍이
  생기면 원시 키가 아니라 한국어로 떨어진다.
- **치환**: `t("msg.stats", { pages, words })`가 `{pages}` 자리를 채운다.
  수치·이름을 문자열 접합으로 만들지 않으므로 어순이 다른 언어를 나중에
  붙일 수 있다.
- **DOM 적용**: `data-i18n`(선행 텍스트 노드), `data-i18n-title`(title),
  `data-i18n-ph`(placeholder). **선행 텍스트 노드만** 건드리므로 메뉴의
  `<kbd>Ctrl+Z</kbd>` 같은 뒤따르는 자식은 언어를 바꿔도 살아남는다.
  적용 후 `<html lang>`도 맞춘다.

부팅 순서가 중요하다. `main.ts`는 wasm(17.5MB)을 초기화하므로 라벨을 거기서
칠하면 수백 ms 동안 빈 메뉴가 보인다. 그래서 `boot.js`를 `main.js` **앞에**
두어 파싱 직후 라벨이 들어간다.

## 2. 추출 결과

| 대상 | 전 | 후 |
|---|---|---|
| `index.html` 한글 리터럴 | 127줄 | **6줄** (글꼴 패밀리명 5 + 언어명 "한국어") |
| `web/src/*.ts` 한글 리터럴 | 60줄 | **11줄** (전부 글꼴 패밀리명 + 주석 1) |
| `data-i18n` / `-title` / `-ph` | – | 97 / 39 / 3 |

글꼴 패밀리명(굴림·바탕·궁서…)은 **문서 데이터이지 UI 문구가 아니다** —
어느 언어로 보든 그 폰트의 이름은 굴림이므로 번역하지 않고 리터럴로 둔다.
언어 선택기의 "한국어"/"English"도 관례대로 각자의 언어로 적는다.

문자열 스윕에서 한글 grep으로는 안 잡히던 **영어 리터럴 2개**도 나왔다
(`"select some text first (Ctrl+B/I/U)"`, `"ready — load the demo or open a
.docx"`). 한국어 UI에서 영어로 뜨고 있던 것들이라 같이 테이블로 옮겼다.
키 커버리지는 스크립트로 교차 검증했다: ko/en 키 집합 동일, 호출부에서
쓰는 키가 테이블에 전부 존재.

## 3. 알려진 한계 (의도)

상태줄 앞부분 `caret: d/1, offset 6 | last op 34.1 ms (2/2 pages redrawn)`는
번역하지 않았다. 이건 제품 문구가 아니라 **진단 출력이고 테스트 계약**이다 —
`hf-test.js`가 `S.lastDelta`를 `/^(\d+)\/(\d+) pages redrawn/`로 파싱한다.
번역하면 그 파싱이 깨지고 얻는 것은 없다. 제대로 된 상태바를 만들 때 함께
정리할 항목으로 남긴다.

## 4. 검증

- **로케일 결정**: 헤드리스 브라우저의 `navigator.language`가 `ko`라
  기본이 한국어(`lang=ko`, 메뉴 "파일"). `?lang=en`이면 `lang=en`,
  메뉴 "File", 툴팁 "Show or hide the toolbar", placeholder "Find",
  스타일 옵션 "Body text".
- **전환**: 선택기를 en으로 바꾸면 `<html lang>`이 즉시 en, 메뉴가 "File",
  `localStorage["rdoc.lang"]="en"`, 그리고 `실행 취소<kbd>Ctrl+Z</kbd>`는
  `Undo<kbd>Ctrl+Z</kbd>`가 되어 **kbd 자식이 보존**된다.
- **런타임 메시지**: `?lang=en`에서 문서 정보 →
  `Pages 2 · paragraphs 23 · words 131 · characters 721 (613 without spaces)`,
  각주 삭제 가드 → `Place the caret in the footnote and press Ctrl+Alt+D`.
- **스크린샷**: `docs/evidence/s63-ui-ko.png`, `docs/evidence/s63-ui-en.png`.
- **테스트 수정 1건**: `stats-test.js`가 상태줄에 "페이지"/"단어"가 있는지
  보고 있었다 — 로케일 의존이라 **숫자(페이지 수·단어 수)를 확인**하도록
  바꿨다. 나머지 49종은 무수정.
- **배터리**: i18n 적용 빌드에서 **50 PASS, 0 FAIL**. 단, 이 실행은 마지막
  두 문자열(`msg.fmtNeedsSel`, `msg.ready`)을 테이블로 옮기기 *직전* 빌드
  기준이다. 최종 빌드는 `tsc` 통과까지만 확인했고 배터리 재실행은
  **하지 못했다** — 서버와 러너가 외부에서 두 번 연속 중단됐다. 두 문자열은
  어떤 스위트도 참조하지 않으므로(`grep "ready|select some text"
  web/tests/*.js` → 0건) 결과가 달라질 이유는 없지만, **실측하지 않았다**는
  사실을 그대로 남긴다.

## 남은 것

- 상태줄 진단 문구(위 §3)는 상태바 재설계 때.
- 언어 추가는 `LOCALES`에 코드 하나와 테이블 파일 하나.
- 데모 문서 내용 자체는 한국어·영어 혼합 그대로 (문서 데이터).
