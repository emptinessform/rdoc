### 근본 원인 — 재시작 페이지네이션 적격 게이트

v0.10.1 `crates/rdocx-layout/src/engine.rs:1236`:

```rust
let restart_record_eligible = sections.len() == 1
    && input.document.background_xml.is_none()
    && input.footnotes.is_none() && input.endnotes.is_none()
    && !document_wraps
    && sections[0].header_footer.is_none()
    && ...all(|(content, block)| restart_record_block_is_safe(block));
// restart_record_block_is_safe: paragraph.lines.len() <= 2
//   && anchored.is_empty() && heading_level.is_none()
//   && !keep_next && !keep_lines && 노트/이미지/그룹 없음
```

**문서 전역 all-or-nothing**이다. 3줄 이상 문단이 **하나라도** 있거나,
각주·미주·머리글/꼬리글이 있으면 문서 전체가 증분 경로에서 빠져
키 입력마다 전체 페이지네이션을 돈다.

0.8(우리 포크 F-X040 후보) `paginator.rs`의 `cacheable`은 ① 단일 섹션
② 블록 지문 존재 ③ 부동 도형 없음 — 이 셋만 본다. 각주·머리글·문단
줄 수는 무관하고, 변경 지점 직전 체크포인트에서 재개한다.

### 대조 실험 (bench2) — 조건 분리 및 가설 반증

`crates/rdoc-core/src/bin/bench2.rs`(신규)로 같은 700문단 문서에서 조건을
하나씩만 바꿔 측정했다 (env: `RDOC_BENCH2_LONG/TABLES/HEADING/NOTES/HF`).
키 입력 mean (ms), 3회 반복:

| 문서 | 0.8 | v0.10.1 |
|---|---|---|
| 기준(1줄 문단 700) | 8 / 8 / 14 | **3 / 5 / 3** |
| + 표 14 | 9 | 5 |
| + 제목 1개 | — | 5 |
| + 머리글·쪽번호 꼬리글 | 8 / 9 / 8 | 5 / 7 / 10 |
| **+ 각주 1개** | 6 / 8 / 10 | **19 / 14 / 16** |
| 4줄 문단 700 + 표 14 (63p) | 31 / 41 | 42 / 52 |

**확정된 것 — 각주 절벽**: 각주가 없으면 v0.10.1이 0.8보다 **2× 빠르다**.
같은 문서에 각주 **1개**만 넣으면 v0.10.1은 자기 대비 4× 느려지고 0.8보다
2× 느려진다. 0.8은 같은 변화에 **전혀 반응하지 않는다**. 코드의
`input.footnotes.is_none()`(문서 전역 조건)과 정확히 대응한다.
머리글/꼬리글도 같은 모양의 약한 효과(3~5 → 5~10 ms)로, v0.10.1의 우위를
지운다 — `sections[0].header_footer.is_none()`.

**반증된 것 — `lines.len() <= 2` 가설**: 포크에 런타임 오버라이드를 심어
(`RDOCX_RESTART_LINE_CAP`, 실험 커밋은 포크 브랜치 `exp/restart-gate`)
63페이지·4줄 문단 문서에서 캡을 2/4/64로 쓸어봤다 — **31~45 ms로 캡 간
구분이 안 된다**. 이 상수는 우리가 본 회귀의 원인이 아니다. 앞선
worklog·CLAUDE.md의 "3줄 이상 문단이 원인" 서술은 **철회한다**.

**남은 미해결**: 4줄 문단 문서에서 v0.10.1이 1.3× 느린 것(42~52 vs
31~41)은 캡이 원인이 아니므로 설명이 없다.

> **정정 (S56b, 2026-08-26)**: 이 1.3×는 **실재하지 않는다**. A/B/A 교차
> 측정에서 같은 빌드의 편차가 ±30%로 나와 효과가 묻혔다 —
> docs/worklog/2026-08-26-s56b-restart-ceiling.md 참조. 위 42~52 수치는
> 무거운 빌드 직후에 잰 값이다. 같은 문서에서 S3 벤치의 2.4×도 같은
> 이유일 가능성이 높다.

## 결론

- **이행 재보류.** 기능은 완전 등가이고 포크는 3커밋 더 슬림해지지만,
  실제 Word 문서(머리글/꼬리글이 있거나 3줄 이상 문단이 있는 문서 =
  사실상 전부)에서 타이핑 1.46×·undo 2.15× 회귀.
- 다만 S55와 달리 **단일 변수 하나가 잡혔다**: 각주 1개가 문서 전역
  증분 경로를 끈다. 각주·머리글을 실격 조건이 아니라 재시작 **식별자**
  (지문)로 접으면 — #40/#41이 `env_fp`로 하던 방식 — 이행이 열릴 여지가
  크다. 각주가 없는 문서에서는 v0.10.1이 이미 0.8보다 2× 빠르다.
- 프로덕션은 svg-poc-0.8(29a4a5c) 유지. 스파이크는 포크 브랜치
  `svg-poc-0.10`, rdoc 브랜치 `s56-v0101-spike`, 적응 패치
  docs/upstream/2026-08-26-rdoc-v0101-adaptation.diff로 보존.
- `crates/rdoc-core/src/bin/bench2.rs`(게이트 대조 벤치)를 main에 추가.
