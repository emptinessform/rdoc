# 2026-08-23 — S52: PDF 저장 (파일 메뉴)

## 목표·범위

파일 메뉴 "PDF로 저장" — 화면과 동일한 폰트(오픈 폰트+별칭)·동일한
리비전 보기로 PDF 다운로드. 업스트림 oxml-pdf 백엔드 재사용,
포크 커밋 없음.

## 한 일

- rdoc-core에 `oxml-pdf` 의존성(default-features off) 추가 —
  `render_to_pdf(&LayoutResult)`가 우리 레이아웃 결과의 `.layout`
  필드를 그대로 받음(엔진 캐시 재사용, 재레이아웃 없음).
- wasm `save_pdf()` — render()와 같은 폰트/별칭/리비전 옵션으로
  레이아웃 후 PDF 바이트 반환(읽기 전용, 히스토리 없음).
- 메뉴 파일 > "PDF로 저장"(rdoc.pdf blob 다운로드), __t.savePdf.
- 네이티브 poc가 out/poc.pdf도 출력(육안 대조용).

## 검증 (실측)

- 네이티브: out/poc.pdf 84,453B, %PDF-1.7, 페이지 객체 2 = 렌더
  페이지 수. **PDF를 직접 열어 육안 대조** — 한글 조판·스타일 런
  (볼드/이탤릭/색/취소선/16pt)·리스트·셰이딩 표·각주·미주·머리글·
  페이지 번호가 화면 SVG 렌더와 동일.
- 브라우저 pdf-test 7단정: %PDF- 시그니처, 페이지 객체 수 = 화면
  페이지 수, FontFile2 폰트 임베딩 확인, 편집 반영(신선한 export),
  추적 보기 PDF ≠ 수락 보기 PDF.
- wasm 번들 12.28MB (S51 후 대비 +~0.3MB 수준 — pdf-writer/subsetter
  추가분).

## 한계·후속
