# 2026-09-07 — S63: localizing the product UI

S62 made the docs bilingual; this stage does the product. UI strings were
pulled out of the sources into locale tables, and the language can now be
switched at runtime.

## 1. Structure

```
web/src/i18n/
  index.ts    78 lines — locale resolution, t(), applyI18n()
  ko.ts      213 lines — 187 keys
  en.ts      211 lines — the same key set
  boot.ts     12 lines — paints the UI before the wasm bootstrap; wires the picker
```

- **Locale resolution order**: `?lang=` → `localStorage("rdoc.lang")` →
  `navigator.language`. Korean gives ko, anything else en.
- **Fallback**: `TABLES[locale][key] ?? ko[key] ?? key`. A hole in the English
  table degrades to Korean rather than to a raw key.
- **Interpolation**: `t("msg.stats", { pages, words })` fills the `{pages}`
  slots. Numbers and names are not concatenated into the string, so a language
  with a different word order can be added later.
- **DOM application**: `data-i18n` (the leading text node), `data-i18n-title`
  (the title attribute), `data-i18n-ph` (placeholder). Only the **leading**
  text node is touched, so trailing children — the `<kbd>Ctrl+Z</kbd>` hints in
  the menus — survive a language switch. `<html lang>` is set to match.

Boot order matters. `main.ts` initializes 17.5MB of wasm, so painting labels
there would leave the menus empty for hundreds of milliseconds. `boot.js` is
therefore loaded **before** `main.js` and fills the labels right after parsing.

## 2. What the extraction found

| Target | Before | After |
|---|---|---|
| Korean literals in `index.html` | 127 lines | **6** (5 font family names + "한국어") |
| Korean literals in `web/src/*.ts` | 60 lines | **11** (all font family names + 1 comment) |
| `data-i18n` / `-title` / `-ph` | – | 97 / 39 / 3 |

Font family names (굴림, 바탕, 궁서…) are **document data, not UI copy** — a
font is called 굴림 in any interface language — so they stay literal. The
language picker's "한국어"/"English" also stay in their own languages, as is
conventional.

The sweep also turned up **two English literals** that a Korean-text grep could
never have found (`"select some text first (Ctrl+B/I/U)"` and
`"ready — load the demo or open a .docx"`) — they had been showing in English
inside the Korean UI, and moved into the tables with everything else. Key
coverage was cross-checked by script: the ko and en key sets are identical, and
every key used at a call site exists in the tables.

## 3. Known limitation (deliberate)

The front of the status line — `caret: d/1, offset 6 | last op 34.1 ms
(2/2 pages redrawn)` — was not translated. It is not product copy but a
**diagnostic with a test contract**: `hf-test.js` parses `S.lastDelta` with
`/^(\d+)\/(\d+) pages redrawn/`. Translating it would break that parse and buy
nothing. It is left for whenever a real status bar replaces this readout.

## 4. Verification

- **Locale resolution**: the headless browser reports `navigator.language` as
  `ko`, so the default is Korean (`lang=ko`, menu "파일"). With `?lang=en`:
  `lang=en`, menu "File", tooltip "Show or hide the toolbar", placeholder
  "Find", style option "Body text".
- **Switching**: setting the picker to en flips `<html lang>` to en
  immediately, the menu to "File", `localStorage["rdoc.lang"]` to "en", and
  `실행 취소<kbd>Ctrl+Z</kbd>` becomes `Undo<kbd>Ctrl+Z</kbd>` — the **kbd
  child survives**.
- **Runtime messages**: under `?lang=en`, document info gives
  `Pages 2 · paragraphs 23 · words 131 · characters 721 (613 without spaces)`
  and the footnote-delete guard gives
  `Place the caret in the footnote and press Ctrl+Alt+D`.
- **Screenshots**: `docs/evidence/s63-ui-ko.png`, `docs/evidence/s63-ui-en.png`.
- **One test changed**: `stats-test.js` asserted that the status line contained
  "페이지" and "단어", which is locale-dependent — it now checks the **numbers**
  (page and word counts) instead. The other 49 suites are untouched.
- **Battery**: **50 PASS, 0 FAIL** on the i18n build. That run was on the
  build from *just before* the last two strings (`msg.fmtNeedsSel`,
  `msg.ready`) moved into the tables. The final build was verified only as far
  as a clean `tsc`; the battery could **not** be re-run — the server and the
  runner were stopped externally twice in a row. No suite references either
  string (`grep "ready|select some text" web/tests/*.js` returns nothing), so
  there is no reason for the result to differ, but it stands recorded that this
  was **not measured**.

## Remaining

- The status-line diagnostics (§3) go with the status bar redesign.
- Adding a language is one code in `LOCALES` plus one table file.
- The demo document's own content stays as it is, Korean and English mixed —
  that is document data.
