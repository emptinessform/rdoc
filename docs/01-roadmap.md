# 로드맵

각 단계는 검증 게이트(실측 증거 + 사용자 확인)를 통과해야 다음으로 넘어간다.
PoC 1~3은 완료 ([worklog/2026-08-21.md](worklog/2026-08-21.md)).

## 완료

- **PoC 1 — SVG 렌더러**: rdocx `LayoutResult` → 자기완결 SVG (글리프 벡터
  내장). 게이트: rdocx PNG 백엔드와 시각적 일치. ✅
- **PoC 2 — wasm**: 브라우저에서 docx 파싱→조판→SVG, 폰트 주입 방식 확립.
  게이트: 100ms 미만 렌더, 한국어 셰이핑. ✅
- **PoC 3 — 히트테스팅/편집 루프**: 클릭→커서→타이핑→재조판. 게이트: 문서
  위치 역매핑 동작 + 편집 반영 실측. ✅ (키 입력당 21~27ms)

## 다음 단계

### S1. 읽기 전용 뷰어 제품화
- 다중 페이지·스크롤·줌, 임의 docx 안정성 (실문서 코퍼스 테스트)
- 렌더러 공백 메우기: 그라디언트, 클립 패스, 그룹 효과
- 텍스트 선택(드래그) + 클립보드 복사
- 게이트: 실제 문서 N종 렌더링 비교 통과, 선택/복사 동작 실측

### S2. 편집 MVP
- 선택 범위 삭제/치환, Enter(문단 분할), 서식 토글(B/I/U)
- undo/redo (커맨드 패턴)
- IME 조합 입력 (한글 — composition 이벤트)
- 게이트: 타이핑 시나리오 자동화 테스트 + 저장한 docx를 Word/rdocx로 재검증

### S3. 구조 편집과 성능
- 표 셀 편집 — 업스트림 provenance(#37 후속) 또는 포크 확장으로 역매핑 대체
- 증분 리레이아웃 (문단 단위 캐시) — 기준선: 현재 전체 재조판 21~27ms/키
- 게이트: 50페이지 문서에서 타이핑 지연 목표치(<30ms) 달성

### S4. 협업·확장
- 코멘트/변경추적 UI (업스트림 M14와 합류)
- MCP 서버 (AI 에이전트가 문서 편집)

## 업스트림 전략

- provenance(레이아웃 출력에 소스 위치)는 S3 전에 업스트림 제안. 거절 시
  rdocx-layout 포크 유지가 공식 노선이 된다 (결정은 decisions.md에 기록).
